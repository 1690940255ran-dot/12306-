# 人不在电脑前，怎么抢票？（2026-09-23）

## 一、先说结论

**本工具无法绕过"本人扫码登录"这一步。** 原因是架构决定的：

- 工具走的是 **12306 网页会话**；
- 网页登录只有两条路：**扫码**（要手机能看到电脑屏幕上的二维码）或**账号密码**（有滑块验证，且工具不该持有你的密码）；
- 而会话**活不过夜**（实测：空闲约 10 分钟失效；保活可续，但见下）。

所以：**"设个定时任务、全程无人扫码"在当前架构下做不到。** 这不是偷懒，是账号安全与 12306 风控的边界。

## 二、四条可走的路（按可行性排序）

### ① 用官方 App 的「候补」——远程场景最靠谱（推荐）

- 候补是**官方支持的排队机制**：提交一次就自动排队，**不需要守在电脑前、不需要抢**；
- 全程在手机上完成，不依赖电脑；
- 热门车次的候补成功率**远高于**硬抢（硬抢是毫秒级竞争，候补是排队）。

> 注：候补要求该乘车日**已开售**（放票后才能提交候补），所以仍需在放票后操作一次手机——但那只需几秒，且不必守在电脑前。

### ② 远程控制家里电脑 + 第二台设备扫码

- 用向日葵 / TeamViewer / Windows 远程桌面连回家里的电脑；
- 电脑上会显示登录二维码 → 用**另一台设备**（平板/备用手机）扫码；
- **限制**：二维码有效期只有几分钟，且必须有两台设备（手机没法扫自己屏幕上的码）。
- 注：12306 App 的「扫一扫」**是否支持从相册识别图片**，我查不到确证，所以"把二维码导出成图片再扫"这条路**不保证可行**。

### ③ 找人代扫

家人/同事在你电脑前点一下"扫码登录"，用你的手机扫一下即可。**扫码本身不需要输入密码**，风险可控。

### ④ 提前扫码 + 定时启动（半自动）

- 你能在开售前 20~30 分钟碰到电脑 → 扫码登录 → 工具挂机保活 → 到点自动抢；
- 定时提醒已支持（本次就给你设了 15:30 的提醒）；
- **但**：现场数据显示"挂机越久，下单越可能被拒"（见下），所以这条路的可用时间窗还在验证中。

## 三、为什么"提前几小时扫码挂机"还不保险

五次现场记录：

| 会话年龄 | 保活 ping 次数 | 下单结果 |
| --- | --- | --- |
| ≤ 36 分钟 | ≤ 2 次 | ✅ 全部成功 |
| ≥ 100 分钟 | ≥ 22 次 | ❌ 全部失败 |

而两种情况下 `checkUser` 都报"有效"——**保活保住的只是表面登录态，没保住"下单资格"**。

**这是"无人值守"的真正拦路虎，比速度更关键。** 分清是"年龄"还是"ping 次数"之后才能给结论：
- 若是 ping 次数 → 换保活方式（改用轻量页面访问）即可让无人值守可行；
- 若是会话年龄 → 只能尽量晚登录，届时我会明确告诉你"做不到全程无人"。

## 四、速度：已开一个 A/B 验证，可能省下 5 秒

下单路径实测：

| 做法 | 确认页核对耗时 |
| --- | --- |
| 复用预热页面 | **2.39 秒** |
| 重新导航（当前默认） | **7.86 秒** |

当初改成"重新导航"，依据是 17:00 那次"复用页面失败"。**但那次失败也可能是会话太老（当天会话已 4 小时 50 分）导致的，跟复用页面无关。**

所以新增了 `order_reuse_page` 开关做 A/B 复验：**若复用页面在新会话下可用，直接省下约 5 秒**——这是目前能找到的最大一笔速度优化。

> 更快的做法（复刻 12306 内部接口）不做：接口/签名随时变、高频直连必被风控打击、本质是爬虫。
> **浏览器方案的地板就是 5~8 秒**，对"1 秒售罄"的热门车次，硬抢本来就不是最优解——候补才是。
