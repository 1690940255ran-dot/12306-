# 多设备同时抢票？——结论与建议（2026-09-23）

## 一、你问的问题

> 下载 12306 的 Windows 版，是不是就能手机和电脑同时抢票了？

## 二、结论：**不建议，而且可能正是失败的原因**

### 1. 12306 同一账号**不支持多设备同时在线**

多个来源一致说明：**同一时间仅限一台设备在线，新设备登录会把旧设备强制下线**
（"会话冲突/被强制下线"）。所以"手机 + 电脑同时抢"这个前提本身就不稳。

### 2. 官方并没有独立的 Windows 桌面客户端（需自行核对）

- 12306 官网（www.12306.cn）主推的是**手机客户端（App）+ 网页版**；
- 微软应用商店里确实有一个名为"铁路12306"的应用，但**我未能确认其发布者是否为官方**
  （中国铁道科学研究院集团有限公司）。请在商店页核对 **"发布者"** 字段——
  不是该主体就不要装，商店里存在名称相似的非官方应用。

### 3. 即使能同时登录，**同一张票也抢不了两次**

同一 **乘车人 + 车次 + 日期** 只能有一张票，系统会去重。
所以"两个通道抢同一张票"在业务上就是多余的——只会互相干扰。

### 4. 这条正好指向我们一直在查的"会话掉线"元凶

| 场景 | 是否掉线 | 证据 |
| --- | --- | --- |
| 只保活，无人操作 | ✅ 5 小时不掉 | 9-21 实测 |
| 保活 + 预热（已开售/未开售） | ✅ 15 分钟不掉 | 9-23 实验两段 |
| 保活 + 预热 + **真实开售时刻开抢** | ❌ **掉线** | 9-22 12:45、9-23 12:45 |

两次失败时**用户都在电脑前**（都刚发过消息，并自述"可能看了"手机 App）；
而 9-23 那次 30 分钟无人操作的实验全程没掉线。
**"在别的设备登录 → 网页会话被踢掉"是目前最符合全部证据的解释。**

## 三、建议做法

1. **抢票期间只用一条通道**：就用本工具（走网页会话），**期间不要打开手机 App、
   不要在别的浏览器/客户端登录同一账号**；
2. 不要在抢票前/中"去 App 里看一眼"——那一下很可能就把会话踢掉了；
3. 如果确实想要第二条通道，用**另一个账号**（家人账号），并且**目标乘车人/车次不要重叠**；
4. 若要装 Windows 客户端，先核对商店页"发布者"是否为官方主体。

## 四、待验证（决定性实验，约 5 分钟）

假设"别处登录会踢掉网页会话"，可这样验证：

1. 我打开网页登录窗 → 你扫码（网页会话建立）；
2. 我校验会话有效（`checkUser flag=true`）；
3. **你去手机 App / 其他设备登录同一账号**；
4. 我再校验一次 —— 若立刻变成无效 → **元凶确认**。

确认之后：不需要改代码，**只要遵守"抢票期间不登录其他设备"**即可；
同时我会在工具里加一条明确提示/启动前检查，避免再踩。

## 五、实验执行结果（14:11–14:21）：**网页会话全程有效** ⚠️ 结论待定

```
[14:11:13] 起始网页会话: 有效 ✅
[14:12:13 … 14:21:14] 第 1–10 次校验：全部有效
结论：观察 600 秒内网页会话始终有效（共校验 10 次）。
```

**关键前提未确认**：这 10 分钟里用户**是否真的在手机 App 登录了同一账号**？

- 若**登录过** → "多设备登录踢掉网页会话"假设**被推翻**；
- 若**没登录** → 实验无效，需重做（这次请务必在观察期内去 App 登录）。

> 注：本次观察期只有 10 分钟、且期间没有任何查询/下单动作；
> 即使假设成立，也可能需要更长时间或"活跃会话"才会触发踢出。
