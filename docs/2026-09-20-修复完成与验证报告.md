## 2. 已完成修复

### 2.1 定点抢票与速度

- 显式 `sale_at` 始终优先，查询页能够打开不再把未来开售时间改成当前时间。
- 预热阶段只打开页面并安装观察器；第一次刷新严格等到开售时刻，不在 T-300 秒提前消耗请求预算。
- 命中后复用当前结果页进入确认订单页，省去账户页跳转、固定等待和重新加载查询页。
- 抢票要求单日期、单席别、明确车次、乘车人、开售时间、`auto_submit` 和有效授权，缺少任一条件都会在启动时失败。
- 从暂停状态显式启动抢票时先合法恢复到监控状态，避免命中后才因状态错误失败。
- 等待采用短时睡眠，不再忙等占满 CPU。

### 2.2 登录与会话

- GUI 抢票与监控统一启用记住登录，不再主动丢弃已保存状态。
- 会话使用 Windows DPAPI 加密保存 Playwright `storage_state` 和 12306 官方域名的 `sessionStorage`；旧版只含 `storage_state` 的文件仍可读取。
- 已确认登录的浏览器关闭前自动保存会话；临时网络异常返回 `UNKNOWN`，不再直接误判为登出。
- 挂机期间每 10 分钟低频检查下单会话；失效时打开官方可见登录页，由用户完成扫码或核验后自动继续。
- CLI 与 GUI 的退出登录共用适配器方法并清除加密状态。

### 2.3 订单安全与幂等

- 订单尝试创建、任务进入 `BOOKING` 和事件记录改为同一数据库事务。
- 自动提交必须再次确认任务开关；准备前和唯一一次提交前都会重新读取任务，校验状态、停止时间、配置版本、授权和页面结果有效期。
- 任务被停止、暂停、到期或配置改变后，旧的准备结果不能继续提交。
- 活动订单尝试禁止物理删除；本地“取消”只适用于尚未发送的 `PREPARED`，避免释放重复下单锁。
- 每个订单尝试记录 `mock/browser` 环境，恢复核对时禁止跨环境处理。
- 提交点击只执行一次；超时或页面含糊时进入 `OUTCOME_UNKNOWN`，随后只核对，不盲目重提。
- 官方未完成订单页只有同时出现本次车次、乘车日期、出发站和到达站，且状态为待支付或排队时才采信。无关订单及帮助文字保持 `UNKNOWN`。
- 乘客票种显式选择成人票或学生票，不再继承页面默认值。

### 2.4 调度、限频与重试

- 调度计划使用绝对 monotonic 时间；多个计划项不会把累计等待重复相加。
- 全局最小请求间隔跨轮保存，并在请求真正开始时才消费预算。
- `wait=False` 遇到未到时间的请求返回 `scheduled`，不会绕过限频立即发送。
- 服务端明确给出的 `Retry-After` 作为最短冷却时间，不受本地自产退避上限截断。
- 熔断器半开阶段只发放一个探测许可，结果返回前禁止并发探测。
- 相同余票持续存在时，若上次在创建订单尝试前因登录等前置条件失败，下一轮会重新预检；一旦同任务版本已创建自动尝试，则不重复创建。

### 2.5 运行、日志与通知

- PowerShell toast 使用 Base64 JSON 传入固定脚本，消息内容不再拼接成可执行命令。
- 起售提醒按 T-10、T-1、T0 的事件记录判断是否错过，不再把已经发送的提醒误报为全部错过。
- 启动 BAT 会先检查虚拟环境解释器和 GUI/浏览器依赖；损坏时显示重建命令，而不是静默启动失败。
- `requirements.lock` 的项目安装改为 `-e .`，移除开发机绝对路径。

## 4. 真实浏览器验收步骤

1. 重建虚拟环境并安装 `.[browser,gui]`，执行 `python -m playwright install chromium`。
2. 使用单独的测试账号/低风险行程，在可见浏览器中完成登录，关闭后重新打开并检查是否无需再次扫码。若官方主动失效或触发风险核验，必须由本人重新完成。
3. 先执行真实只读查询，确认站名、日期、车次和席别解析正确；页面结构不同应熔断并报错。
4. 创建未来开售的测试任务，观察预热阶段不刷新，到 `sale_at` 才出现第一笔刷新请求。
5. 首次真实订单验收必须人工监督：核对确认页车次、日期、区间、乘车人、票种、席别和总价；只允许一次提交；支付由本人完成。
6. 制造一次提交超时或关闭页面，确认本地进入结果不明/核对状态，且没有第二次提交。
7. 在官方页面处理完订单后运行核对，确认只有身份指纹一致的订单才改变本地状态。

## 5. 保留限制

- 真实候补流程未实现，能力保持关闭。
- 官方页面和风控规则可能变化；页面结构变化时工具会停止自动操作，需要重新做现场验收。
- 会话持久化可减少本地造成的重复扫码，但不能绕过官方主动过期、异地登录、短信、滑块或人脸核验。
- 轮询间隔下限保持 2 秒；工具不会通过高频请求规避官方限制。
- 当前损坏的 `.venv` 没有在离线修复中自动删除或联网重装；启动器会明确提示重建步骤。
